You are a senior DevOps architect, VPN protocol expert, and full-stack engineer.
Your task is to DESIGN AND IMPLEMENT a COMPLETE, PRODUCTION-READY VPN SYSTEM
that supports ALL major VPN protocols, runs on MULTIPLE operating systems,
and includes INSTALLER, USER MANAGEMENT, MONITORING, and OUTPUT GENERATION.

════════════════════════════════════════════════════════════
🎯 CORE GOALS (NON-NEGOTIABLE)
════════════════════════════════════════════════════════════
1. Support MULTIPLE VPN PROTOCOLS (selectable by admin):
   - Xray-based: VLESS, VMess, Trojan, Shadowsocks
   - Tunnel-based: WireGuard, OpenVPN
   - Optional/Advanced: SOCKS5, HTTP Proxy, REALITY

2. Admin ONLY selects the PROTOCOL.
   - DO NOT ask user to select transport.
   - System MUST auto-generate ALL supported transports
     for the chosen protocol.

3. ONE USER ACCOUNT must automatically generate MULTIPLE OUTPUT CONFIGS:
   - WS TLS
   - WS Non-TLS
   - gRPC
   - TCP (if applicable)
   - Any protocol-specific variants

4. EVERY VPN ACCOUNT MUST HAVE A HOST.
   - No account without host/domain.
   - Host must be an entity, not just a string.

5. System MUST be INSTALLABLE on MULTIPLE OS:
   - Ubuntu / Debian
   - CentOS / Rocky / Alma / Alibaba Cloud Linux
   - (Optional) Arch-based
   - Detect OS automatically and adapt package manager & service config.

════════════════════════════════════════════════════════════
🏗️ ARCHITECTURE REQUIREMENTS
════════════════════════════════════════════════════════════
- Use a MODULAR ARCHITECTURE with clear separation:
  - Core Engine
  - Protocol Adapters
  - Transport Presets
  - Host Manager
  - User Manager
  - Monitoring Engine
  - Output Generator

- FOLLOW THIS ABSTRACTION:
  HOST → INBOUND (GLOBAL) → USER → MULTI OUTPUT

- NEVER create inbounds per user.
- Inbounds are GLOBAL and reusable.
- Users are protocol-bound but transport-agnostic.
